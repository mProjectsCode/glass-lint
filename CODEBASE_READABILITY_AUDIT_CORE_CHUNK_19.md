# Codebase Readability Audit — glass-lint-core Chunk 19: Lifecycle and value queries

## Summary

Chunk 19 covers the public authoring boundary for bounded lifecycle queries and
static-value/argument constraints: `api::rule::query::lifecycle` (builders,
endpoint, types, sealed adapters), `api::rule::query::canonical`,
`api::rule::query::limits`, `api::rule::query::value`, `api::rule::taxonomy`
(`Confidence`), `rule_id` (`RuleId`), the `rules` top-level facade, and
`api/rule/mod.rs`. Compiler IR stays private; only validated semantic
constructors are exposed. The declarator types themselves
(`EventQuery`/`LifecycleQuery`/`QueryDecl`) are audited in chunk 18; this
chunk owns the builder surfaces, the taxonomy/rule-id types, and the
deferred/immediate error machinery built on `FirstError`.

The core abstractions are well-executed: `CanonicalCollection` and
`ArgumentConstraints` are genuinely owned invariant collections, the sealed
adapter family is generated by one macro and re-used consistently, and
`LifecycleSink` internally shares one `build_call_sink` path across its four
constructors. The main costs are (1) a duplicated two-style
deferred-error/immediate builder pattern implemented once for `Rule` and again
for `LifecycleQuery`, where the lifecycle immediate surface (`LifecycleQueryBuilder`
+ `LifecycleBuilderState`) is neither exported nor documented and is reached
only by the crate's own unit tests, while the `RuleBuilder` immediate surface
is exported and documented but has no production caller; (2) a
`LifecycleEventBuilder` ceremony that duplicates `EventQuery`'s argument-building
idiom with a hand-written sealed seam; and (3) invariants the lifecycle modules
hand-roll for sources where `CanonicalCollection` already owns them.

Seven findings, ranked by severity. No fixes applied.

## Findings

### Lifecycle builder architecture

#### [x] READ-001 — The deferred/immediate builder machinery is duplicated across `Rule` and `LifecycleQuery`, and the lifecycle immediate surface is test-only

- **Severity:** High
- **Fix Complexity:** High
- **Theme:** SIMPLIFY
- **Category:** Architecture | Duplication
- **Location:** `glass-lint-core/src/api/rule/mod.rs:13-40,137-262,264-314` and `glass-lint-core/src/api/rule/query/lifecycle.rs:115-252`

`FirstError` + `record_first_error` (`api/rule/mod.rs:13-40`) are shared
correctly, but the builder shape built on them is painted onto each domain:
`RuleBuilder` (infallible fluent methods that record duplicates into
`duplicate_field`, plus `try_query`/`try_queries` that return `Result`,
mod.rs:137-262) wrapped by `CatalogRuleBuilder` (mod.rs:264-314), and the
lifecycle twin `LifecycleQueryBuilder` + `LifecycleBuilderState.invalid_operation`
+ `try_source`/`try_condition`/`try_completion` + `CatalogLifecycleQueryBuilder`
(lifecycle.rs:115-252). Both domains agree on the only production route — the
deferred catalog builder: `Rule::catalog_builder` (~90 call sites in
`glass-lint-js`/`glass-lint-obsidian`) and `LifecycleQuery::catalog_builder`
(every production lifecycle authoring file
`-js/src/rules/browser/{file_dialog,remote_resource,script_injection}`, plus
`glass-lint-core/examples/query_declarations.rs:73,102`). The reachability of
the immediate surface differs per domain, which is the crux: `RuleBuilder` is
exported by the `rules` facade (lib.rs:55) and documented as the
immediate-error path (`query/mod.rs:11`, README.md:38), but `LifecycleQueryBuilder`
is never re-exported (lib.rs:50-56; lifecycle.rs:10-17 re-export only value
types and kinds) and has no documented or production caller — it is reached
only by the crate's unit tests (`api/rule/tests.rs:63,102`;
`lifecycle/tests.rs:45-60,437-442`). `LifecycleBuilderState` exists only to
hold `invalid_operation`, which no non-test path ever populates: the catalog
route records into its own `first_error` (`lifecycle.rs:226,231-242`) and never
touches `record_operation`. So the lifecycle side carries an extra layer
(`LifecycleBuilderState`) plus a publicly reachable API that real callers never
use, layered on the same design already implemented for `Rule`.

**Recommendation:** Collapse the lifecycle side onto the single catalog shape.
Keep `CatalogLifecycleQueryBuilder` as the only lifecycle builder, wrapping
`LifecycleStages` directly and recording into its one `first_error` — the
stages' `try_source`/`try_condition`/`try_completion` (lifecycle.rs:44-69)
already return `Result`, so the wrapper needs no inner builder; delete
`LifecycleBuilderState` and `LifecycleQueryBuilder`, and rewrite the two
immediate tests to the catalog style (the deferred duplicate test at
lifecycle/tests.rs:24-42 already covers the same `DuplicateLifecycleStage`
outcome that the immediate test at 45-60 checks). On the Rule side, keep the
documented and exported `RuleBuilder` immediate surface (`try_query`,
`try_queries`, duplicate recording) but extract one shared deferred-record
builder governor so `CatalogRuleBuilder` and `CatalogLifecycleQueryBuilder` are
shaped by a single helper instead of two near-identical wrappers. Guardrails:
preserve the distinct error values (`DuplicateLifecycleStage`, `DuplicateField`),
deterministic first-error ordering, the `LifecycleStages::build` validation
sequence (lifecycle.rs:78-104), and the public `rules::` exports —
`LifecycleQuery`, `LifecycleSink`, and the `CatalogRuleBuilder` names all
remain; any `try_*` helper surfaced on the catalog builder must keep the same
conversion and duplicate-check order the stages apply today.

**Fix Applied:** Removed the test-only lifecycle immediate builder and made
`CatalogLifecycleQueryBuilder` wrap `LifecycleStages` directly. Added a shared
private `DeferredBuilder` governor used by both catalog builders to retain the
first fallible authoring error while preserving stage validation order. Updated
lifecycle tests to exercise duplicate and malformed-source errors through the
remaining catalog path. Verified with `cargo test -p glass-lint-core api::rule::query::lifecycle`.

### Lifecycle event construction

#### [ ] READ-002 — `LifecycleEventBuilder` re-implements the `EventQuery::with_arg` idiom with a `build()` ceremony and a hand-written sealed adapter

- **Severity:** Medium
- **Fix Complexity:** Medium
- **Theme:** SIMPLIFY
- **Category:** API | Complexity
- **Location:** `glass-lint-core/src/api/rule/query/lifecycle/types.rs:70-116,395-399`

`LifecycleEvent::member_call` returns a `Result<LifecycleEventBuilder, _>`
(types.rs:70-84) so callers chain `.arg(i, m)?` and then `.build()`, wrapping
the result in `Ok(...)` to fit `IntoLifecycleEvent`
(`file_dialog/mod.rs:31-37`, `remote_resource/mod.rs:84-91`). The identical
operation on `EventQuery` is a direct `with_arg(index, matcher) -> Result<Self>`
on the value itself (`query/constructors.rs:261-280`, used in the same files).
The builder adds a third type, a separate `.build()` step, and the only
hand-written `IntoLifecycleEvent` impl and `private::Sealed` impl in the file
(types.rs:112-116, 395-399 — every other adapter is macro-generated by
`define_lifecycle_adapter!`, types.rs:11-34). It is also `pub` yet unreachable
outside the crate (never re-exported in the `rules` facade), so its public
marker is meaningless to external authoring code.

**Recommendation:** Drop `LifecycleEventBuilder` and mutate `LifecycleEvent`
directly, mirroring `EventQuery::with_arg`: keep the private
`LifecycleEventKind::MemberCall` starting with empty `ArgumentConstraints`
(types.rs:78-83) and add a validated `with_arg`/`arg` on `LifecycleEvent` that
pushes through `ArgumentConstraints::push`, returning `Self` by value.
Delete the builder type, its `IntoLifecycleEvent` impl, and the manual `Sealed`
impl, letting the macro cover all sealed types. Guardrails: keep `member_call`
validating the chain (empty check + `checked_chain`, types.rs:74-77) exactly as
today, keep the argument-index validation via `ArgumentIndex::try_from_usize`
in the new `with_arg` (as `arg` does today, types.rs:98), keep `property_write`
unchanged, and rewrite the affected provider call sites to the shorter
`with_arg` chain, preserving the `Ok(...)` wrapper that keeps the `any_of`
array homogeneous (`Result<LifecycleEvent, _>` through the macro-generated
adapter). The `with_arg` addition must be checked against the same
`MAX_PREDICATES_PER_ARGUMENT` / `MAX_ARGUMENT_GROUPS` bounds that
`ArgumentConstraints::push` enforces today (value.rs:296,302).

**Fix Applied:** None so far.

### Canonical invariant reuse

#### [ ] READ-003 — Lifecycle sources re-implement `CanonicalCollection`'s non-empty/bounded/sorted/dedup invariants by hand

- **Severity:** Medium
- **Fix Complexity:** Low
- **Theme:** DEDUPLICATE
- **Category:** Duplication | Encapsulation
- **Location:** `glass-lint-core/src/api/rule/query/lifecycle.rs:81-94` and `glass-lint-core/src/api/rule/query/canonical.rs:12-40`

Conditions and completions obtain their canonical shape from the single owner
(`CanonicalCollection::collect` via `LifecycleEvents::new`/`LifecycleSinks::new`,
types.rs:134-147,215-228), but `LifecycleStages::build` re-implements the same
three invariants inline for sources: empty check (lifecycle.rs:81-83), bound
check (84-89), and `sort()`+`dedup()` (93-94). Every other consumer in the
chunk delegates these rules to `CanonicalCollection` (value.rs:73-112). The
behavior is equivalent: the over-limit count and the empty-error label map 1:1
onto `collect`'s arguments (`MAX_LIFECYCLE_SOURCES`,
`QueryBuildError::MissingLifecycleSources`, label `"lifecycle sources"`).

**Recommendation:** In `LifecycleStages::build`, collect the accumulated
sources through `CanonicalCollection::collect(…, MAX_LIFECYCLE_SOURCES,
MissingLifecycleSources, "lifecycle sources", |e| Ok(e))?.into_vec()` instead
of the hand-rolled sequence, removing the duplicated sort/dedup/bound code from
the builder so the "canonical collection" contract has a single implementation.
Guardrails: confirm the `CollectionTooLarge` count and `MissingLifecycleSources`
error are byte-for-byte the same as today (they are: 64 collected then a 65th
item reports 65, matching `len==65 > 64` today), and keep `sources` a sorted,
deduplicated `Vec<EventQuery>` since `LifecycleQuery::sources()` exposes it and
normalization depends on canonical order (normalize.rs:255-281). The one
precedence difference to pin with a test: `collect` rejects an overflowing item
before converting it, so an invalid 65th source surfaces as
`CollectionTooLarge` rather than the item's own conversion error — accept that
difference deliberately or keep the empty-check before the size check, as the
hand-rolled code does today.

**Fix Applied:** None so far.

### Public surface and namespacing

#### [x] READ-004 — `rules` facade is the only reachable public boundary but omits `pub` types the inner module claims to export

- **Severity:** Medium
- **Fix Complexity:** Low
- **Theme:** ENCAPSULATE
- **Category:** API | Encapsulation
- **Location:** `glass-lint-core/src/lib.rs:4,49-57`, `glass-lint-core/src/api/rule/mod.rs:48-57`, `glass-lint-core/src/api/rule/query/value.rs:9-29,250-271`, `glass-lint-core/src/api/rule/query/lifecycle/types.rs:87-88`

`mod api` is private (lib.rs:16), so `api/rule/mod.rs:56` marking
`ArgumentConstraint` and `ArgumentIndex`
`pub use query::value::{…, ArgumentConstraint, ArgumentIndex, …}` makes them
unreachable to any external caller — the `rules` facade at lib.rs:49-57 is the
single real manifest and it re-exports `ArgumentMatcher` and `ValueMatcher` but
omits exactly `ArgumentConstraint`/`ArgumentIndex`. The crate-level doc
intensifies the mismatch: it advertises [`rules::ArgumentIndex`] as a public
rule value that remains stable across compilation (lib.rs:4), an intra-doc link
that cannot resolve against the current facade.
`LifecycleEventBuilder` is similarly `pub` within a `pub(crate)` tree and is
never re-exported. Providers rely on `rules::` (116 imports); none of these
three types is nameable or needed there (constraints are added through
`with_arg`/`EventRequirement::argument`, which exercise the types internally).
The facade and the inner `pub` markers disagree about what is public.

**Recommendation:** Make the `rules` facade the single canonical decision: since
the crate doc already names `ArgumentIndex` as public, export `ArgumentIndex`
(and matching `ArgumentConstraint`) there — the smaller, doc-consistent change;
otherwise downgrade both to `pub(crate)` alongside `LifecycleEventBuilder` and
fix the crate doc. Massage the `pub use` at api/rule/mod.rs:48-57 to match the
facade so `pub` means "externally reachable" in exactly one place. Guardrails:
keep the crate-internal paths (`ArgumentIndex::try_from_usize`,
`ArgumentConstraint::new`, the `kind()` accessors used by the compiler at
`api/compiler/normalize.rs` and `analysis/flow/matcher.rs`) intact; the
public-surface integration test (`tests/integration/public_surface.rs`) already
builds rules through the catalog route without engine storage and must keep
passing.

**Fix Applied:** Added `ArgumentIndex` and `ArgumentConstraint` to the
crate's canonical `rules` facade, matching the crate documentation and the
existing public re-exports from the authoring module. Internal compiler paths
and lifecycle-builder visibility remain unchanged.

### Rule identifier validation

#### [ ] READ-005 — The provider-local rule-name check runs twice: `RuleBuilder::build` and `RuleCatalog::new`

- **Severity:** Low
- **Fix Complexity:** Low
- **Theme:** DEDUPLICATE
- **Category:** Duplication | Newtype
- **Location:** `glass-lint-core/src/api/rule/mod.rs:247-253`, `glass-lint-core/src/lint/catalog.rs:105-115`, and `glass-lint-core/src/rule_id.rs:30-40`

`RuleBuilder::build` trims the local `id` and validates it with
`RuleId::valid_name` (api/rule/mod.rs:247-253, rule_id.rs:19-21) and then stores
it as a bare `String` on `Rule`. The only consumer that promotes a rule into
catalog identity is `RuleCatalog::new` (grep confirms `Vec<Rule>` is accepted
nowhere else, catalog.rs:102), and it re-runs the identical `valid_name` check
inside `RuleId::from_provider_and_name` (catalog.rs:112, rule_id.rs:34-38)
before assembling `provider:name`; the provider part is likewise validated twice
(catalog.rs:105-107 and again at rule_id.rs:34). The invariant "rule id is a
valid provider-local name segment" is therefore enforced at two layers, and
`Rule::id` holds the value as an untyped `String` rather than reusing the
validated semantic type that `rule_id.rs` already defines.

**Recommendation:** Keep validation at exactly one authoritative boundary and
give `Rule`'s id field the validated semantics: have `RuleBuilder::build`
construct `RuleId::valid_name`-checked storage (or a small `ProviderLocalName`
newtype that reuses the `valid_part` core, rule_id.rs:60-78), returning
`RuleBuildError::InvalidId`, and let `RuleCatalog::new` trust the name part
while still producing the namespaced `RuleId` via `from_provider_and_name` and
still validating the provider part itself. Guardrails: `Rule` must keep its
provider-local, dot-hierarchical names (e.g. `"lifecycle.events"`) distinct
from the namespaced `provider:name` form; the catalog must still reject an
invalid provider argument that produces an invalid namespaced id; update
fixtures/providers only if the `Rule::id()` accessor spelling changes.

**Fix Applied:** None so far.

### Test-only accessors and dead weight

#### [x] READ-006 — `LifecycleSink::chain()` and the test-scoped `len()` wrappers duplicate accessors already provided by the endpoint and the canonical collection

- **Severity:** Low
- **Fix Complexity:** Low
- **Theme:** SIMPLIFY
- **Category:** Encapsulation | Other
- **Location:** `glass-lint-core/src/api/rule/query/lifecycle/types.rs:149-157,230-238,376-382`

`LifecycleSink::chain()` (types.rs:376-382) has no production caller at all. The
only production reader of the chain spelling is `explain_lifecycle_sink`
(explanation.rs:260-268), which reaches `endpoint.chain()` directly through
`sink.kind()` (explanation.rs:263,266); the compiler's normalizer also matches
`sink.kind()` but reads only `endpoint.target()` and `index.get()` — never the
chain (`normalize_lifecycle_sink`, normalize.rs:356-372). Only
`lifecycle/tests.rs:340,350` use `sink.chain()`. Similarly,
`CanonicalCollection::len` (canonical.rs:46-49) is re-exposed as test-only
`len()` on both `LifecycleEvents` and `LifecycleSinks` (types.rs:153-156,
234-237) purely so the unit tests can assert canonical orderings. These
accessors widen the surface of crate-internal types without a production
consumer.

**Recommendation:** Delete `LifecycleSink::chain()` after changing
`lifecycle/tests.rs:340,350` to assert through `sink.kind()` and
`endpoint.chain()`; likewise drop the duplicated test-len wrappers and let the
tests compare whole `LifecycleEvents`/`LifecycleSinks` values (they already
assert canonical equality, e.g. tests.rs:106-119) or gate a single
`CanonicalCollection::len`. Guardrails: keep the ordered/deduped invariants
observable so the order-independence tests at lifecycle/tests.rs:123-130 and
172-197 remain sharp; do not remove `CanonicalCollection::collect`, `iter`, or
`into_vec`, which production callers (value.rs:73-112, types.rs:149-151,230-232,
normalize.rs) rely on.

**Fix Applied:** Removed the unused `LifecycleSink::chain()` forwarder and
test-only collection `len()` wrappers. Lifecycle tests now inspect endpoint
spelling through `sink.kind()` and count canonical collections through their
existing iterators.

### Value matcher composition

#### [x] READ-007 — `ValueMatcher`'s seed/transform transition silently overwrites the current kind

- **Severity:** Low
- **Fix Complexity:** Low
- **Theme:** SIMPLIFY
- **Category:** API | Complexity
- **Location:** `glass-lint-core/src/api/rule/query/value.rs:114-179`

Every static-string method takes `self` and calls `with_static_predicate`,
which unconditionally assigns `ValueMatcherKind::StaticString(...)`
(value.rs:116-119). The intended base seed is `ValueMatcher::static_string()`
(value.rs:128-135, the `StaticString(Any)` seed), but a caller who writes
`ValueMatcher::any_value().try_equals("x")` silently ends up with an exact
static-string matcher — the `any_value()` choice is discarded with no error and
no doc note. The `StaticString(Any)` seed is also reachable as a final value
(`static_string()` alone), so the "predicate on top of a seed" contract is
implied by the API shape but not enforced. No current caller relies on the
overwrite: every predicate chain in `glass-lint-js`, `glass-lint-obsidian`, and
`examples/query_declarations.rs` starts from `ValueMatcher::static_string()`
(`any_value()` is used only as a terminal value).

**Recommendation:** Make the transform explicit: have the `try_equals`/
`equals_any`/`starts_with_any`/`contains_any`/`contains_all` family (or a single
`with_static_predicate`) reject a non-`StaticString` base with
`QueryBuildError` instead of overwriting, or replace the seed pattern with
self-contained constructors (e.g. `ValueMatcher::exact("x")`) so the reshape
cannot mask a caller's intent. Guardrails: keep `any_value()` and
`static_string()` usable and keep all existing provider call sites
(`remote_resource`, `file_dialog`, `query_declarations`) compiling — since none
chains a predicate off `any_value()` today, the rejection is safe to ship, but
pin the guard with a negative unit test asserting `any_value().try_equals(..)`
errors rather than silently converting.

**Fix Applied:** Static-string predicate methods now reject a non-static-string
seed with `StaticStringMatcherRequired` instead of silently replacing the
matcher kind. Added a negative test for `any_value().try_equals(...)`; existing
static-string chains remain unchanged.

## Systemic Themes

- **Two-style deferred/immediate builders, asymmetric reachability.** `FirstError` +
  `record_first_error` plus infallible-fluent and `try_*` variants are
  implemented per domain (`Rule` and `LifecycleQuery`). In both domains the
  deferred catalog builder is the only production path. But the two halves are
  not symmetric: `RuleBuilder` is exported (`rules::RuleBuilder`, lib.rs:55)
  and documented as the immediate-error route (query/mod.rs:11), while
  `LifecycleQueryBuilder` is neither exported nor documented and is reachable
  only from unit tests, with an extra `LifecycleBuilderState` layer whose only
  field (`invalid_operation`) is never populated on the catalog route. Collapse
  the lifecycle side onto the single deferred catalog builder and dedupe the
  deferred-record governor shared by both catalog wrappers.
- **`pub` in private trees, and a facade that disagrees with its own doc.**
  `ArgumentIndex`, `ArgumentConstraint`, `LifecycleEventBuilder`,
  `LifecycleQueryBuilder` use `pub` where the module path is `pub(crate)` or
  `mod api` is private (lib.rs:16), so `pub` does not mean externally
  reachable; the `rules` facade (lib.rs:49-57) is the real manifest, yet it
  omits `ArgumentIndex`/`ArgumentConstraint` while the crate doc (lib.rs:4)
  advertises `[rules::ArgumentIndex]` as public. The facade should be the
  single source of truth.
- **Canonical invariants are well-owned — except sources.** `CanonicalCollection`
  and `ArgumentConstraints` are strong domain collections; the one place that
  hand-rolls bounded/empty/sorted/dedup (`LifecycleStages::build` for sources,
  lifecycle.rs:81-94) stands out and should delegate.
- **Sealed adapter family is coherent.** The `define_lifecycle_adapter!` macro
  generates the `Value` + `Result<Value, _>` impls and `Sealed` impls in one
  place; the only hand-written seam is `LifecycleEventBuilder`, which disappears
  with READ-002.

## Open Questions — Resolved

1. **The lifecycle event's bare `MemberChain` is intentionally identity-looser,
   and it should stay that way.** A lifecycle event's `MemberCall` is a
   *requirement on the tracked object* — a method invoked on the object whose
   lifecycle is being correlated (`el.setAttribute(...)`). The compiler lowers
   it to `CompiledObjectRequirement::MemberCall { member: SymbolPath, .. }`
   (`object_flow.rs:228-231`) and matches it against an actual tracked object's
   member path via `FlowMatchView::member_matches` (`planning.rs:66-68`,
   `355-368`), with requirement members looked up through the name table
   (`planning.rs:306-317`). The `Global(name)` vs `RootedMember(path)`
   distinction (`endpoint.rs:9-13`) exists only for source/sink *endpoints* —
   call targets that receive the object — which select candidate flows through
   `BoundTargetIndex` keyed on `BoundLifecycleCallTarget` (`planning.rs:77-83`,
   `101-122`). Event requirements never enter that namespace, so carrying the
   target kind would be dead weight. The one-segment form (`setAttribute`) is
   normalized to a `SymbolPath` (`object_flow.rs:229`) and matched loosely
   (`actual == expected || actual.last_segment() == expected.last_segment()`,
   planning.rs:67), which is exactly the authoring intent for "the tracked
   object has this method called on it". No change needed; READ-002's collapse
   must preserve the `MemberChain`-only storage.
2. **The immediate builders are *not* slated to become a shared public surface —
   but the two are not symmetric.** `RuleBuilder` is deliberately public:
   exported by the facade (`rules::RuleBuilder`, lib.rs:55), named as the
   immediate-error path in the module doc (query/mod.rs:11), and shown in the
   crate README (README.md:38 — the example is stale, using a removed
   `category()` method, so it is weak evidence, but the export and module doc
   are current). `LifecycleQueryBuilder`, by contrast, is not exported
   (lib.rs:50-56; lifecycle.rs:10-17), is not documented, and has callers only
   in lifecycle/tests.rs:45-60,437-442. So READ-001 is a *deletion* for the
   lifecycle immediate surface plus a *dedup into one deferred-record governor*
   for the two catalog wrappers — not a deletion of `RuleBuilder`, whose
   documented immediate surface is a deliberate public contract.
3. **The double name-part check is duplication today, not defense-in-depth.**
   `Rule` is produced only by `Rule::builder`/`catalog_builder` and consumed
   only by `RuleCatalog::new` (`Vec<Rule>` appears nowhere else, catalog.rs:102;
   `RuleSelection`/`RuleOverride` operate on namespaced selectors, not `Rule`
   values). The build-time `valid_name` check (mod.rs:251) and the re-check
   inside `from_provider_and_name` (rule_id.rs:34) therefore both run on the
   exact same value in every production path; the provider part is also
   validated twice (catalog.rs:105-107 and rule_id.rs:34). Defense-in-depth
   would only matter if a non-catalog consumer could later accept a `Rule`, and
   since a `Rule`'s queries must be compiled to be useful, the catalog is the
   only sensible consumer. READ-005's single-boundary validation is safe.
4. **The symbol check must stay deferred at build time.** The lifecycle symbol
   is free-form evidence prose with spaces (`"file input element"`,
   `"remote script element"`, `"fetch result"` — see file_dialog/mod.rs:17,
   remote_resource/mod.rs:20, lifecycle/tests.rs:90), not a validated
   identifier, so the `checked_name` validator (declarations.rs:50-56) does not
   apply. The public entry points `LifecycleQuery::builder` and
   `catalog_builder` take `impl Into<String>` and return the builder infallibly
   (lifecycle.rs:254-266), so moving the `trim().is_empty()` check to
   construction would require making both constructors fallible or inventing a
   validated newtype for a prose label — disproportionate. Keeping the check at
   `build` (lifecycle.rs:78-80) matches the deferred-error design of the
   builder and yields `EmptyEvidenceSymbol` at the same point today.
5. **`ArgumentIndex`/`ArgumentConstraint` are not needed by any downstream
   authoring tool, so READ-004 can resolve either way — but the crate doc makes
   exporting the smaller change.** No reference to either type exists outside
   core: grep across `glass-lint-js`, `glass-lint-obsidian`, `glass-lint-harness`,
   `glass-lint-output`, and `examples/` finds none (integration tests only match
   `QueryBuildError::InvalidArgumentIndex` strings, e.g.
   `tests/integration/query/composition.rs:429,437,457`). Constraints are
   always authored through `with_arg`/`EventRequirement::argument`. Because the
   crate doc already advertises `[rules::ArgumentIndex]` as public (lib.rs:4),
   exporting both types in the facade is the doc-consistent, smaller change;
   downgrading to `pub(crate)` is the alternative if the doc is corrected
   instead.
