# Codebase Readability Audit — glass-lint-core Chunk 19: Lifecycle and value queries

## Summary

Chunk 19 covers the public authoring boundary for bounded lifecycle queries and
static-value/argument constraints: `api::rule::query::lifecycle` (builders,
endpoint, types, sealed adapters), `api::rule::query::canonical`,
`api::rule::query::limits`, `api::rule::query::value`, `api::rule::taxonomy`
(`Confidence`), `rule_id` (`RuleId`), the `rules` top-level facade, and
`api/rule/mod.rs`. Compiler IR stays private; only validated semantic
constructors are exposed.

The core abstractions are well-executed: `CanonicalCollection` and
`ArgumentConstraints` are genuinely owned invariant collections, the sealed
adapter family is generated by one macro and re-used consistently, and
`LifecycleSink` internally shares one `build_call_sink` path across its four
constructors. The main costs are (1) a duplicated two-style
deferred-error/immediate builder pattern implemented once for `Rule` and again
for `LifecycleQuery`, where the "immediate" builder surface is exercised only
by the crate's own unit tests; (2) a `LifecycleEventBuilder` ceremony that
duplicates `EventQuery`'s argument-building idiom; and (3) invariants the
lifecycle modules hand-roll where `CanonicalCollection` already owns them.

Seven findings, ranked by severity. No fixes applied.

## Findings

### Lifecycle builder architecture

#### [ ] READ-001 — The deferred/immediate builder machinery is duplicated across `Rule` and `LifecycleQuery`, and the immediate surface is only used in tests

- **Severity:** High
- **Fix Complexity:** High
- **Theme:** SIMPLIFY
- **Category:** Architecture | Duplication
- **Location:** `glass-lint-core/src/api/rule/mod.rs:13-40,137-262,264-314` and `glass-lint-core/src/api/rule/query/lifecycle.rs:115-252`

`FirstError` + `record_first_error` (`api/rule/mod.rs:13-40`) back a pair of
builders in each domain: `Rule::builder`/`RuleBuilder` (infallible fluent
methods that record errors into `duplicate_field`, plus `try_query`/
`try_queries` that return `Result`) and a wrapper `CatalogRuleBuilder`
(lifecycle.rs pattern counterpart `LifecycleQueryBuilder` +
`LifecycleBuilderState.invalid_operation` + `try_source/condition/completion`
+ `CatalogLifecycleQueryBuilder`, lifecycle.rs:115-252). The two are the same
design painted onto a second domain. In both domains the production surface is
exclusively the deferred catalog builder (`Rule::catalog_builder` ~90 provider
call sites in `glass-lint-js`/`glass-lint-obsidian`; every `LifecycleQuery`
production caller `-js/src/rules/browser/{file_dialog,remote_resource,script_injection}`)
while the "immediate" builders are reached only by the crate's unit tests
(`api/rule/tests.rs:63,102`; `lifecycle/tests.rs:45-60,437-442`).
`LifecycleBuilderState` exists only to hold `invalid_operation`, which no
non-test path ever populates on the catalog route (the catalog records into its
own `first_error` instead). This is repeated machinery with a redundant layer
and a publicly reachable API that real callers never use.

**Recommendation:** Collapse to one pattern. Keep the deferred
`CatalogLifecycleQueryBuilder` (already the only production path) over
`LifecycleStages`, delete `LifecycleBuilderState` and the 
`LifecycleQueryBuilder` immediate surface (`try_source`, `try_condition`,
`try_completion`, and the infallible recording `source`/`condition`/
`completion`), and let callers who want immediate errors use `?` through the
same `try_add_*` helpers. Mirror the deletion for `RuleBuilder`'s `try_*` +
`duplicate_field` recording, or at minimum extract one shared deferred-record
builder governor. Guardrails: preserve the distinct error values
(`DuplicateLifecycleStage`, `DuplicateField`), deterministic first-error
ordering, the `LifecycleStages::build` validation sequence, and update the
unit tests in `lifecycle/tests.rs` and `api/rule/tests.rs` to the catalog
style. Do not change the public `rules::` exports: `LifecycleQuery`,
`LifecycleSink`, and the `CatalogRuleBuilder` names all remain.

**Fix Applied:** None so far.

### Lifecycle event construction

#### [ ] READ-002 — `LifecycleEventBuilder` re-implements the `EventQuery::with_arg` idiom with a `build()` ceremony and a hand-written sealed adapter

- **Severity:** Medium
- **Fix Complexity:** Medium
- **Theme:** SIMPLIFY
- **Category:** API | Complexity
- **Location:** `glass-lint-core/src/api/rule/query/lifecycle/types.rs:70-116,395-399`

`LifecycleEvent::member_call` returns a `Result<LifecycleEventBuilder, _>`
(types.rs:71-84) so callers chain `.arg(i, m)?` and then `.build()`, wrapping
the result in `Ok(...)` to fit `IntoLifecycleEvent`
(`file_dialog/mod.rs:31-37`, `remote_resource/mod.rs:84-91`). The identical
operation on `EventQuery` is a direct `with_arg(index, matcher) -> Result<Self>`
on the value itself (`query/constructors.rs:261-280`, used in the same files).
The builder adds a third type, a separate `.build()` step, and the only
hand-written `IntoLifecycleEvent` impl and `private::Sealed` impl in the file
(types.rs:112-116, 395-399 — every other adapter is macro-generated). It is
also `pub` yet unreachable outside the crate (never re-exported in the `rules`
facade), so its public marker is meaningless to external authoring code.

**Recommendation:** Drop `LifecycleEventBuilder` and mutate
`LifecycleEvent` directly, mirroring `EventQuery::with_arg`: keep the private
`LifecycleEventKind::MemberCall` starting with empty `ArgumentConstraints` and
add a validated `with_arg`/`arg` on `LifecycleEvent` that pushes through
`ArgumentConstraints::push`. Delete the builder type, its `IntoLifecycleEvent`
impl, and the manual `Sealed` impl, letting the macro cover all sealed types.
Guardrails: keep `member_call` validating the chain and argument index
(`try_from_usize`) exactly as today, keep `property_write` unchanged, and
rewrite the affected provider call sites to the shorter `with_arg` chain. The
`arg` addition must be checked against the same `MAX_PREDICATES_PER_ARGUMENT`
/ `MAX_ARGUMENT_GROUPS` bounds.

**Fix Applied:** None so far.

### Canonical invariant reuse

#### [ ] READ-003 — Lifecycle sources re-implement `CanonicalCollection`'s non-empty/bounded/sorted/dedup invariants by hand

- **Severity:** Medium
- **Fix Complexity:** Low
- **Theme:** DEDUPLICATE
- **Category:** Duplication | Encapsulation
- **Location:** `glass-lint-core/src/api/rule/query/lifecycle.rs:81-94` and `glass-lint-core/src/api/rule/query/canonical.rs:12-40`

Conditions and completions obtain their canonical shape from the single owner
(`CanonicalCollection::collect` via `LifecycleEvents::new`/`LifecycleSinks::new`,
types.rs:134-147,215-228), but `LifecycleStages::build` re-implements the same
three invariants inline for sources: empty check (lifecycle.rs:81-83), bound
check (84-89), and `sort()`+`dedup()` (93-94). Every other consumer in the
chunk delegates these rules to `CanonicalCollection`. The behavior is
equivalent: the over-limit count and the empty-error label map 1:1 onto
`collect`'s arguments (`MAX_LIFECYCLE_SOURCES`,
`QueryBuildError::MissingLifecycleSources`, label `"lifecycle sources"`).

**Recommendation:** In `LifecycleStages::build`, collect the accumulated
sources through `CanonicalCollection::collect(…, MAX_LIFECYCLE_SOURCES,
MissingLifecycleSources, "lifecycle sources", |e| Ok(e))?.into_vec()` instead
of the hand-rolled sequence, removing the duplicated sort/dedup/bound code from
the builder so the "canonical collection" contract has a single implementation.
Guardrails: confirm the `CollectionTooLarge` count and `MissingLifecycleSources`
error are byte-for-byte the same as today (they are: 64 collected then a 65th
item reports 65, matching `len==65 > 64` today), and keep `sources` a sorted,
deduplicated `Vec<EventQuery>` since `LifecycleQuery::sources()` exposes it and
normalization depends on canonical order.

**Fix Applied:** None so far.

### Public surface and namespacing

#### [ ] READ-004 — `rules` facade is the only reachable public boundary but omits `pub` types the inner module claims to export

- **Severity:** Medium
- **Fix Complexity:** Low
- **Theme:** ENCAPSULATE
- **Category:** API | Encapsulation
- **Location:** `glass-lint-core/src/lib.rs:49-57`, `glass-lint-core/src/api/rule/mod.rs:48-56`, `glass-lint-core/src/api/rule/query/value.rs:9-29,250-271`, `glass-lint-core/src/api/rule/query/lifecycle/types.rs:87-88`

`mod api` is private (lib.rs:16), so `api/rule/mod.rs:56` marking
`ArgumentConstraint` and `ArgumentIndex`
`pub use query::value::{…, ArgumentConstraint, ArgumentIndex, …}` makes them
unreachable to any external caller — the `rules` facade at lib.rs:50-56 is the
single real manifest and it re-exports `ArgumentMatcher` and `ValueMatcher` but
omits exactly `ArgumentConstraint`/`ArgumentIndex`.
`LifecycleEventBuilder` is similarly `pub` within a `pub(crate)` tree and is
never re-exported. Providers rely on `rules::` (116 imports); none of these
three types is nameable or needed there (constraints are added through
`with_arg`/`EventRequirement::argument`, which exercise the types internally).
The facade and the inner `pub` markers disagree about what is public.

**Recommendation:** Make the `rules` facade the single canonical decision:
either export `ArgumentIndex` and `ArgumentConstraint` there (if external rule
authors need to name them) or downgrade them to `pub(crate)` alongside
`LifecycleEventBuilder`, keeping only truly authoring-facing types in `pub`.
Massage the `pub use` at api/rule/mod.rs:56 to match the facade so `pub` means
"externally reachable". Guardrails: keep the crate-internal paths
(`ArgumentIndex::try_from_usize`, `ArgumentConstraint::new`, the `kind()`
accessors used by the compiler at `api/compiler/normalize.rs` and
`analysis/flow/matcher.rs`) intact; the public-surface integration test
(`tests/integration/public_surface.rs`) already builds rules without engine
storage and must keep passing.

**Fix Applied:** None so far.

### Rule identifier validation

#### [ ] READ-005 — The provider-local rule-name check runs twice: `Rule::build` and `RuleCatalog::new`

- **Severity:** Low
- **Fix Complexity:** Low
- **Theme:** DEDUPLICATE
- **Category:** Duplication | Newtype
- **Location:** `glass-lint-core/src/api/rule/mod.rs:247-253` and `glass-lint-core/src/lint/catalog.rs:104-115`

`RuleBuilder::build` validates the local `id` with `RuleId::valid_name`
(api/rule/mod.rs:251) and then stores it as a bare `String` on `Rule`. The only
consumer that promotes a rule into catalog identity re-runs the identical
`valid_name` check inside `RuleId::from_provider_and_name` (catalog.rs:112,
rule_id.rs:34-38) before assembling `provider:name`. The invariant "rule id is a
valid provider-local name segment" is therefore enforced at two layers, and
`Rule::id` holds the value as an untyped `String` rather than reusing the
validated semantic type that `rule_id.rs` already defines.

**Recommendation:** Keep validation at exactly one authoritative boundary and
give `Rule`'s id field the validated semantics: have `RuleBuilder::build`
construct `RuleId::valid_name`-checked storage (or a small `ProviderLocalName`
newtype that reuses the `valid_part` core), returning
`RuleBuildError::InvalidId`, and let `RuleCatalog::new` trust it while still
producing the namespaced `RuleId` via `from_provider_and_name`. Guardrails:
`Rule` must keep its provider-local, dot-hierarchical names (e.g.
`"lifecycle.events"`) distinct from the namespaced `provider:name` form; the
catalog must still reject a provider override that produces an invalid
namespaced id; update fixture/providers only if the `Rule::id()` accessor
spelling changes.

**Fix Applied:** None so far.

### Test-only accessors and dead weight

#### [ ] READ-006 — `LifecycleSink::chain()` and the test-scoped `len()` wrappers duplicate accessors already provided by the endpoint and the canonical collection

- **Severity:** Low
- **Fix Complexity:** Low
- **Theme:** SIMPLIFY
- **Category:** Encapsulation | Other
- **Location:** `glass-lint-core/src/api/rule/query/lifecycle/types.rs:149-157,230-238,376-382`

`LifecycleSink::chain()` (types.rs:376-382) has no production caller — every
consumer reads `endpoint.chain()` via `sink.kind()` (e.g.
`explanation.rs:260-268`, the compiler in `api/compiler/normalize.rs:360-368`);
only `lifecycle/tests.rs:340,350` use it. Similarly, `CanonicalCollection::len`
(canonical.rs:46-49) is re-exposed as test-only `len()` on both
`LifecycleEvents` and `LifecycleSinks` (types.rs:153-156, 234-237) purely so the
unit tests can assert canonical orderings. These accessors widen the surface of
crate-internal types without a production consumer.

**Recommendation:** Delete `LifecycleSink::chain()` after changing
`lifecycle/tests.rs:340,350` to assert through `sink.kind()`/
`endpoint.chain()`; likewise drop the duplicated test-len wrappers and let the
tests compare whole `LifecycleEvents`/`LifecycleSinks` values (they already
assert canonical equality, e.g. tests.rs:106-119) or gate a single
`CanonicalCollection::len`. Guardrails: keep the ordered/deduped invariants
observable so the order-independence tests at lifecycle/tests.rs:123-128 and
172-197 remain sharp; do not remove `CanonicalCollection::collect`, `iter`, or
`into_vec`, which production callers (value.rs:73-112, normalize.rs) rely on.

**Fix Applied:** None so far.

### Value matcher composition

#### [ ] READ-007 — `ValueMatcher`'s seed/transform transition silently overwrites the current kind

- **Severity:** Low
- **Fix Complexity:** Low
- **Theme:** SIMPLIFY
- **Category:** API | Complexity
- **Location:** `glass-lint-core/src/api/rule/query/value.rs:114-179`

Every static-string method takes `self` and calls `with_static_predicate`,
which unconditionally assigns `ValueMatcherKind::StaticString(...)`
(value.rs:116-119). The intended base seed is `ValueMatcher::static_string()`
(value.rs:129-135, the `StaticString(Any)` seed), but a caller who writes
`ValueMatcher::any_value().try_equals("x")` silently ends up with an exact
static-string matcher — the `any_value()` choice is discarded with no error and
no doc note. The `StaticString(Any)` seed is also reachable as a final value
(`static_string()` alone), so the "predicate on top of a seed" contract is
implied by the API shape but not enforced.

**Recommendation:** Make the transform explicit: have the `try_equals`/
`equals_any`/`starts_with_any`/`contains_any`/`contains_all` family (or a single
`with_static_predicate`) reject a non-`StaticString` base with
`QueryBuildError` instead of overwriting, or replace the seed pattern with
self-contained constructors (e.g. `ValueMatcher::exact("x")`) so the reshape
cannot mask a caller's intent. Guardrails: keep `any_value()` and
`static_string()` usable and keep all existing provider call sites
(`remote_resource`, `file_dialog`, `query_declarations`) compiling, updating
any that relied on the overwrite.

**Fix Applied:** None so far.

## Systemic Themes

- **Two-style deferred/immediate builders.** `FirstError` +
  `record_first_error` plus infallible-fluent and `try_*` variants are
  implemented per domain (`Rule` and `LifecycleQuery`); in both domains the
  deferred catalog builder is the only production path and the immediate
  builder is test-only. Consolidate the pattern while deleting the unused
  surface.
- **`pub` in private trees.** `ArgumentIndex`, `ArgumentConstraint`,
  `LifecycleEventBuilder`, `LifecycleQueryBuilder` use `pub` where the module
  path is `pub(crate)` or `mod api` is private, so `pub` does not mean
  externally reachable; the `rules` facade (lib.rs:49-57) is the real manifest
  and should be the single source of truth.
- **Canonical invariants are well-owned — except sources.** `CanonicalCollection`
  and `ArgumentConstraints` are strong domain collections; the one place that
  hand-rolls bounded/empty/sorted/dedup (`LifecycleStages::build` for sources)
  stands out and should delegate.
- **Sealed adapter family is coherent.** The `define_lifecycle_adapter!` macro
  generates the `Value` + `Result<Value, _>` impls and `Sealed` impls in one
  place; the only hand-written seam is `LifecycleEventBuilder`, which disappears
  with READ-002.

## Open Questions

- `LifecycleEvent::member_call` stores a bare `MemberChain`, while
  `LifecycleSink` distinguishes `Global(name)` from `RootedMember(path)`
  (lifecycle/endpoint.rs:10-13). Is the event intentionally identity-looser than
  the sink, or should the event carry the same target kind? Compiler
  normalization (`api/compiler/normalize.rs:339-368`) consumes both shapes, so
  answering this requires knowing how the flow engine models a tracked-object
  method call.
- Are `LifecycleQuery::builder`/`Rule::builder` (immediate style) slated for
  external authors in a future release, justifying keeping both styles even
  though no caller uses them today? This determines whether READ-001 is a
  deletion or a dedup-into-one-governor.
- `RuleBuilder::build` enforces the name-part check (api/rule/mod.rs:251) and
  `RuleCatalog::new` re-enforces it via `from_provider_and_name`
  (catalog.rs:112). If `Rule` can be consumed by a non-catalog path in the
  future, the recorded double check may be intended defense-in-depth rather
  than duplication — worth a confirm before applying READ-005.
- `LifecycleStages::build` validates `symbol.trim().is_empty()` at build time
  (lifecycle.rs:78-80) even though all constructors are builder-mediated. Is an
  earlier (constructor-time) symbol check feasible, or must it stay deferred to
  keep `From`/`Into<String>` ergonomics?
- The `rules` facade intentionally keeps the authoring surface small; READ-004's
  resolution (export vs `pub(crate)`) depends on whether downstream authoring
  tooling (harness, output, future providers) needs to name
  `ArgumentIndex`/`ArgumentConstraint`.
